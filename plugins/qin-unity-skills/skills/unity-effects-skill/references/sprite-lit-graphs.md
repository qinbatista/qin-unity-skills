# Author a 2D sprite shader

## Start with the renderer

Follow the material from its active SpriteRenderer or TilemapRenderer to the shader Unity actually draws. Record the Editor, URP and Shader Graph package versions, active camera renderer, sorting layer, material property references and per-renderer overrides. For a batch, inventory the game-owned materials first. Group shared graphs by renderer, visible behavior and inputs. Edit each shared graph once and test its distinct consumers. Preserve asset GUIDs and property references used by materials, animations and scripts.

Author the 2D surface as an editable **Shader Graph**. For a world sprite in URP, start from **URP Sprite Lit Shader Graph** and use the game's Renderer 2D. Keep artistic colors HDR by default. A specific emissive requirement can justify a different lighting model. Record the visual requirement and exercise it in the receiving camera. For a Canvas widget, fullscreen operation, VFX output or mesh drawn in a 2D scene, choose a Shader Graph target compatible with that actual draw and verify its lighting contract. Route a 3D surface to the [mesh material rules](graph-and-shader.md#author-a-3d-mesh-material). [Unity Sprite Lit graph](https://docs.unity3d.com/6000.0/Documentation/Manual/urp/prebuilt-shader-graphs-urp-sprite-lit.html)

## Wire a minimal lit tint

Start with the [editable Sprite Lit Tint graph](../assets/SpriteLitTint.shadergraph) for a minimal URP 17.6 example. Import it under the receiving project’s shader owner. Its five working nodes use one texture sample and one HDR color control.

1. Create a material from the graph and assign it to the real sprite renderer. Use the installed Sprite Lit template's renderer-bound main texture reference (normally `_MainTex`) and sprite UV0. Sample it once with **Sample Texture 2D** in **Default** mode. A copied sampler in **Normal** mode unpacks channels and changes the artwork. To diagnose a color mismatch, send its raw sampled RGB to Base Color at unit white light and compare the same texels with the original. Check two different sprites sharing the material, including an atlas entry if the game packs sprites.
2. Expose **Tint** as a Blackboard **Color** in **HDR** mode with white as its neutral value. Set artistic Color nodes to HDR too. Connect sampled RGB × Tint RGB to **Base Color**. Connect sampled A × Tint A to **Alpha** when tint alpha controls opacity. Leave HDR RGB unclamped. Keep masks, coverage, normal vectors and data textures in their native types. In URP 17.6 the default Sprite Lit pass applies renderer tint after the graph. The installed 17.6 template can disable automatic tint and wire Vertex Color explicitly. When adapting that template, retain one renderer-tint path. The minimal example enables automatic tint and applies only the artist's material tint in its nodes. Test partial renderer tint and alpha to catch double multiplication. [Shader Graph Color node](https://docs.unity3d.com/Packages/com.unity.shadergraph@17.6/manual/Color-Node.html)
3. Preserve the template's default normal and mask when the surface uses neither. For directional relief, sample the sprite's bound normal texture as a Normal and connect its tangent-space vector to **Normal (Tangent Space)**. For light blend-style masking, bind the game's corresponding channels to **Sprite Mask**. Silhouette coverage belongs in **Alpha**. Sprite Lit shades Base Color with the scene's 2D lights. Overbright Base Color alone does not create an independent emission pass.
4. Extend only the visible job. For a hit flash, interpolate sampled RGB towards an HDR flash color with one scalar and keep the original coverage. For a dissolve, sample one threshold field, form a soft mask with Smoothstep and multiply coverage by it. Share the field with any edge tint. Use sprite UVs for atlas sampling and a separate, defined local coordinate for a per-sprite gradient or distortion. Check packed edges, flipping and skinning where used.

## Lay out the editable graph

Arrange data from left to right. Place texture reads and artist controls before the effect calculation and put the Master Stack after composition. Use titled Shader Graph **Groups** as frames around nodes that jointly produce one result, such as “Sample sprite”, “Reveal edge” and “Compose coverage”. A simple tint can fit in one frame plus the stack. Give preview-expanded nodes and long port names room. Reopen the saved graph, follow the actual wires and check for overlaps, crossings that obscure inputs, orphaned controls and off-screen islands.

Add a **Sticky Note** beside the decision it explains. State what enters and leaves that group and why the graph uses that space, alpha convention, threshold or precision. For example, “Use sprite alpha here so a bright flash keeps the painted silhouette.” Explain effect-specific choices in the graph itself. Keep property names, units, ranges and neutral defaults useful to the artist. Preserve this layout when an authoring tool regenerates a graph. [Unity graph grouping](https://docs.unity3d.com/Packages/com.unity.shadergraph@17.6/manual/Keyboard-shortcuts.html) · [Sticky Notes](https://docs.unity3d.com/Packages/com.unity.shadergraph@17.6/manual/Sticky-Notes.html)

## Choose nodes or a helper

Use built-in nodes for sampling, tint, masks, UV transforms, interpolation and straightforward arithmetic. Use a named Sub Graph for a repeated connected operation. Before adding code, identify the operation the installed nodes cannot express clearly or efficiently. A bounded derivative filter, specialized reconstruction or an existing tested numerical routine can justify a Custom Function. Expose its typed inputs and outputs in the graph, wire it into the live stack and put a short rationale in its frame. Keep sprite sampling, composition and output inspectable wherever practical.

For file mode, keep the guarded HLSL include with the graph's owner. The node's function name is the base name. Implement the matching precision-suffixed entry point, port order and out parameters required by the installed package. Keep its GUID and transitive includes available on import. Test bypass and active settings on the target backend. [Unity Custom Function node](https://docs.unity3d.com/Packages/com.unity.shadergraph@17.6/manual/Custom-Function-Node.html)

## Verify the rendered shader

- Render the assigned material through the intended game camera with a graphics-enabled Unity runner. Check graph import, compiler messages, live target/pass, required texture bindings and the before/after pixels. Retain a view of the actual subject with the result.
- On a fixed sprite with fixed exposure and other light sources controlled, change a Light 2D affecting its sorting layer between two nonzero intensities. Compare an interior region and a transparent exterior. Also move a local light across a normal-mapped region when directional response is part of the design.
- For each artistic HDR control, check the imported HDR flag and change a neutral color to an overbright value at fixed lighting. Read scene-linear RGB from a floating-point render target before tonemapping, grading and Bloom. Verify the affected channel exceeds one when the material promises that range. When migrating a standard Color property to HDR, replay the original material beside the candidate in the project color space. Compare a midtone as well as white. Migrate serialized presets and runtime color setters where the GPU receives different values, then repeat the comparison. Read coverage separately and check soft and fully transparent edges. A PNG communicates appearance; it cannot certify unclipped HDR.
- Check neutral, intermediate and maximum effect settings on the real sprite at gameplay scale. Capture the relevant motion interval for animated materials. For a replacement, compare baseline and candidate at matched inputs, including sorting and per-renderer overrides. Record the scope and any difference for each distinct consumer.
- Trace the live nodes to the used stage outputs. Consolidate duplicate texture samples at identical coordinates and sampler state, remove unused work, and check transparent screen coverage, actual passes and variants. Keep the clearer graph when it produces the same result and cost. Use matched coverage, object count and capture settings to substantiate any timing improvement.
