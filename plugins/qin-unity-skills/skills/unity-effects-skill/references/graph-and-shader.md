# Graph and shader production

## Choose the input

For a design-led effect, locate the exact ability, form and version in the game design. Mark who causes the event, where it lands, and when the gameplay owner can finish or interrupt it. Freeze a timed target GIF with its editable source. Then find an editable reference by the mechanism that makes the gesture readable. For a source conversion, open the selected original prefab and its dependencies first. Inspect its active systems and preview, then freeze the target at the receiving camera. In both cases retain the original identity, relevant source members, orientation, scale and event times.

Map donor emitters and painted components to [independent motion jobs](staged-effects.md#decompose-every-visible-object). Keep the true gameplay clock and [author both live graphs](#author-the-live-graphs). Check the receiving prefab and its nested dependencies, including inactive children, for legacy Particle System components and renderers.

## Rebuild from declared inputs

When a reviewer asks whether an effect can be reproduced, list the exact requested outputs and the files allowed as inputs. Record the owning Skill, versioned recipe or authoring command, reference identity and required Editor and package versions for **each case**. Identify any hand-authored Shader Graph, VFX Graph, texture, prefab or controller among the inputs.

1. Rebuild the timing study twice from its declared artwork, donor or procedural recipe in empty output folders. Compare the decoded frame sequence and exposure times. Keep an encoded reference or screenshot outside the generator inputs unless it is the declared source for a crop or transcode.
2. For a generated runtime asset, run its authoring entry twice with that destination, its importer cache and any cached copy absent. In each receiving project, select and save the target render pipeline before graph compilation. Read back a compiled property and the actual shader binding. Record the input and output identities. Compare events and visible landmarks with the original and the two independently generated results. Fresh Unity assets can have different GUIDs or local file IDs. Verify the references resolve within each build and disclose any byte differences.
3. A hand-authored asset can be tested by two clean imports and independent plays, and by a separate receiving project for a portability claim. Include transitive shader files referenced by path inside serialized VFX custom code. Decode embedded strings so escaped newlines before `#include` are visible. Include controller types stored inline in prefab serialization along with script GUID dependencies. In the empty project select the pipeline, reimport Shader Graphs before their VFX Graph consumers, then check the compiled bindings and visible output. Name each editable input and the parts that still need an author.
4. For a batch, keep one row per case with its source, build command, native actor or effect, case-specific negative control and result. Keep reference fidelity, reconstruction, clean playback, transfer and reviewer approval as distinct claims. Record each missing step alongside that case.

## Author the live graphs

1. Read the receiving project's Editor revision, pipeline, renderer and locked VFX Graph and Shader Graph versions. Inspect a working graph and the installed package's output and target types. Use the current supported node model for those versions. Record the selected types and versions. A planned package upgrade has its own project scope.
2. In the production `.vfx`, connect the spawn event or rate to Initialize, Update and the supported particle Output Context. Initialize local state and seeds, advance transport and forces in Update, and bind the visible attribute streams at Output. Use the current composed Shader Graph output when the installed package provides it. Inspect the saved context edges, blocks and actual output binding after import.
3. The production material entry is a `.shadergraph` with the receiving pipeline's supported Target and a live Master Stack. For a particle output, enable VFX support on its target and assign it to the actual Output Context. A separately sorted mesh or sprite uses its material's assigned Shader Graph. Connect exposed controls to the vertex or fragment blocks that produce each visible job. Hinge masks and object-space vertex motion can animate wings, while shaft UVs transport filaments independently of beam aim. Give vertex deformation enough geometry to bend.
4. Prefer built-in nodes and reusable Sub Graphs. Use a Custom Function node and an HLSL include for a bounded calculation that the graph consumes. Keep coordinates, units, parameters and visible outputs editable and inspectable in the graph. Trace the actual material or VFX output to that asset and neutralize one motion input during a matched native draw. Save the observed local change, restore the input and replay. A standalone ShaderLab file, disconnected graph or global time property cannot establish this binding.

Match each draw to the renderer that executes it. In URP Renderer2D, a skinned SpriteRenderer needs the sprite target, object-space input, native skin deformation and sprite flip. An unlit mesh carrying a beam needs a mesh-compatible pass selected by Renderer2D. A composed particle output needs a VFX-compatible surface. Check all three in their actual non-origin poses and inspect the rendered pixels. If the battle actor lends its material, test the real rig as well as the preview sprite, including facing, cancellation and restoration of the previous binding.

For Unity 6 with VFX Graph 17.6, select a compatible render-pipeline Target, enable **Support VFX Graph**, and set the Shader Graph property on the particle Shader Graph mesh, planar primitive or strip output used by the effect. Check the equivalent types in the installed manual for other package versions. [Unity VFX Graph 17.6 output compatibility](https://docs.unity3d.com/Packages/com.unity.visualeffectgraph@17.6/manual/sg-working-with.html) · [Shader Graph Custom Function node](https://docs.unity3d.com/Packages/com.unity.shadergraph@17.6/manual/Custom-Function-Node.html)

## Translate the executing source

| Editable source | VFX Graph and shader work | Native check |
| --- | --- | --- |
| Burst, rate, start delay, duration and looping | Use the corresponding spawn event or rate. Initialize each particle once with its seed, lifetime and local or world origin. Bound capacity using the overlapping live population. | Step across first emission, the loop seam, stop and retrigger. Look for an accidental second initial event or an unbounded tail. |
| Shape, angle, start speed, velocity, force, damping and noise | Transform the donor axes into the receiving frame. Integrate motion in Update, retaining state between frames. Supply independent noise variation from the stable seed. | Track a feature across time. Move the emitter to distinguish attached, local and already-released world-space motion. |
| Size, color over lifetime, atlas and renderer streams | Evaluate normalized particle age in the right domain. Set size, angle, frame, color and alpha at the actual output. Match the atlas orientation, blend mode and premultiplication to the receiver. | Inspect a single early, middle and late particle against light and dark backgrounds. A square quad, multiplied alpha or repeated atlas cell often becomes visible here. |
| Collision, death or subemission | Follow source file IDs to the actual event and children. Carry the contact position, normal and one event per intended impact into the receiving Graph or gameplay event. Bound the children's independent tails. | Vary contact height or position. The child must follow contact, maintain ordering and retire after the parent. |
| Mesh expansion, trails, rings and ribbons | Match mesh axes, winding and pivot to the camera. Preserve thickness independently from radius, trail history independently from the moving origin, and the advance of the visible edge independently from opacity. | Sample front position, width and interior visibility at several phases. Look for a filled flash, a reversed front or a trail that moves as one rigid card. |

## Select the visible mechanism

| Gesture | Motion and shading decisions | Visible landmark |
| --- | --- | --- |
| Directed launch, jet or fork | Launch along the gameplay axis. Start branches at the split with inherited tangent, then vary divergence and tip speed. Reveal a taper along distance and erode the tail with a mask. | A common stem appears before two tips. Reversing facing mirrors the whole gesture. |
| Wave, crest or outward shock | Drive the front with a decelerating radius or travelling crest. Measure width in receiving units. Shade a leading edge with a softer, broken wake. | A transparent interior opens and the front arrives before the falling wake. |
| Drop, splash and ripple | Give the falling bead a stretched profile, issue one contact, then spread a planar ripple and short divergent droplets at that point. | No ripple precedes contact. The ring remains at the contact while the splash changes height. |
| Drifting embers or swirling dust | Give each particle independent life, drift and phase. For a vortex, combine tangential motion, inward/outward radius and axial lift. Use atlas variation and a soft density gradient. | Persistent flow shows multiple particle ages. Changing direction or camera reveals the winding and the open core. |
| Inward channel, orbit or sustained aura | Advance a phase around the correct anchor, bind inward motion to that center and give the core and outer travel distinct clocks. Shade front and back at their appropriate depths. | The center stays registered on a moving subject. Releasing the input stops new material and the tail drains. |
| Delayed strike or echo | Start the second emission from the specified event, place it on its own path and carry the first tail through the gap. Give each contact a local shader response. | Two distinct contacts survive at gameplay speed and the first tail does not obscure the second startup. |

## Animate fire, water and local variation

Assign regions to the motion visible in the source. Fire can feed from an anchored core, stretch tongues along the flow, erode their flanks and release cooling embers with separate ages. Water can carry a coherent crest into contact, break its lip into falling droplets and spread a thin rim along the surface while the interior clears. Let the Graph drive birth, transport and lifetime. Let the shader carry surface detail along the local flow, with a different rate or correlation length across it. Use particle density, overlap, depth and coverage to convey the material's volume at the receiving camera.

Seed each region and particle at birth. Vary local timing, velocity, phase, width or lifetime within the source's range while retaining coherent travel and the gameplay clock. A rotating carrier can convey the overall gesture. A flame, spray or fluid surface also needs visible internal flow, breakup or replacement over its life. Check both with the [motion and seed comparison](rendering-and-verification.md#verify-internal-motion-and-seed-variation).

### Build water as moving material

**HARD REQUIREMENT FOR WATER.** In the standalone GIF, trace where the water comes from, how the main volume moves, what bends or tears its edge and where it goes after contact or release. Show every applicable phase through the last visible water. Choose editable Shader and VFX references for the specific mechanisms and record the parts already supported by the game's renderer. Use an article or the reviewed GIF for an uncovered mechanism.

- Guide highlights, thickness and gaps in the local direction of transport. Parameterize curved sheets and rims along their surface and vary velocity across their width. Keep a readable transparent region. Add foam selectively at an active crest, tear or contact, and use a soft, curved free edge. A level edge needs support from the actual waterline or contact plane.
- Give detached liquid the position and momentum of the parent region where appropriate. Apply bounded inertia, gravity, drag and individual age or size variation. A contact ripple or spray appears only after its own contact, spreads in the receiving plane and decays separately. A vessel, pool or sustained surface may conserve its outline while the water flows inside it.
- Inspect the isolated film, each responding draw and the composite in two independent native runs at the same times. During an established interval, compare local detail direction with the shader flow frozen while the runtime carrier keeps moving. Check for repeated bright lanes that read as fabric and for uniform shrinkage where the brief calls for a moving collision, rupture or spill. Compare a changed seed without retiming the event. Record the verified timing and geometry as well as any pixel tolerance.

#### Use a thin shader surface for prescribed water motion

A play-timed curtain, cascade or wave can use a shared, bounded mesh with a Shader Graph vertex deformation and a separate surface-flow phase. Shape its advancing edge, crest, closing folds and floor response from the contact time. Keep the overlapping faces transparent and concentrate grazing reflections in narrow, varying bands. Inspect the surface over the intended subject. Broad glossy forms and opaque interior highlights can make a thin film read as oil.

When the brief calls for a rupture, release local regions at different times. Begin each detached piece at its current surface position and velocity. Carry its surface detail with the moving geometry and start runoff where it reaches the receiving plane. Compare the isolated sheet at the same time with reduced gravity or a moved receiving plane. The comparison should change its falling silhouette and contact time while the attached motion stays aligned.

Choose the coordinates and landmarks that match the water. Use a radiating surface for an impact crown and compare the first contact, rising rim, detached spray and widening ground packet. For an advancing breaker, bind the rolling lip to the live crest. Inspect whether the front overtakes the base, where it falls, and how far the thinner swash travels after it. For a hit on a curved boundary, propagate local flow in the surface coordinates. Inspect the arrival of each branch at its own lower edge and trace any detached drops from those paths.

When water should bend scene colour, trace the receiving renderer's same-frame colour capture and place the water draw after that capture. In URP 2D, the Camera Sorting Layer Texture can include earlier sprite layers. Sample it with the film's local flow and constrain the optical blend to the animated water coverage. Compare the same textured background and time with the optics off, with zero screen displacement, and with colour reversal removed if that effect is authored. Measure the shared background copy at idle and under representative overlap.

Use VFX Graph for detached beads and spray at the required count. Launch them from the current sheet or contact plane, stagger their birth and bound their lifetime and live population. Compare flow with its phase held while the sheet still deforms. Confirm that a stopped cast gates new births and drains its visible tail. Review the complete frame at the intended camera, then measure the old and new implementations at the same resolution, action and representative overlap. Record transparent draw count, allocations, texture or simulation work, and the timing statistic with its actual backend and runtime scope.

#### Simulate the body when its motion depends on fluid interaction

**HARD REQUIREMENT FOR REQUESTED FLUID SIMULATION.** Store and advance the water's state between ticks. Choose the simplest model that supports the gesture. A height field suits confined shallow ripples. Particles with pressure or a velocity field can handle merging sheets, splash and falling water. Bind forcing to the gameplay event, move water under gravity and momentum, and let boundary contact, pressure and separation change the next state. Record the force, collision geometry, units, step size, seed and limits in the motion GIF and replay inputs.

Use VFX Graph Update or a compute shader for the simulation. Connect both the visible film and any dependent droplets or contact response to its state or events. Use Shader Graph to reconstruct coverage and thickness or to shade a transported surface. Derive highlights from the moving surface and keep optical strength independent from mass. If the first pass reads as gel, inspect it over a visible subject and tune transmission, wet rims and droplet breakup at the same camera and clock.

Check the full gesture in the two native replays. Record a state sample appropriate to the model, such as a particle position, velocity, occupied height or contact time. Freeze state while keeping the render path live. Disable one causal term and compare its expected change in the measured state and the corresponding crop. Change the seed at the same trigger to test variation. Report the simulation domain and tested graphics backend when delivering the GIF and original-to-native comparison.

#### Compose fluid from a source, moving body and responses

Classify each local example by its inlet, state and dimensionality, applied force, boundary, and visible outputs. Count a parent effect and its material or timing variants once. Open the editable source for each transferred mechanism. List locally available bytes separately from catalog identifiers and downloadable archives.

Keep the water recipe editable independently of its renderer. Carry an impact position and momentum into a receiving height field. Reconstruct falling or colliding volumes from the same moving state that feeds spray. Expose only the boundaries the solver handles. Distinguish the dimension of that state from its projection in the camera.

In the timed GIF mark the last free-flight frame, first contact and the following response. Record the same inlet with and without the boundary. For a swirl, remove torque while retaining gravity and the same inlet. For a ripple, withhold the impulse and measure travel away from the source. Check that a falling mass stays together until contact, that the reference reads at gameplay size, and that the shader has no visible rectangular cutoff. Use a second native replay, a new seed, and a pooled interruption. Profile a single instance and the expected overlap on the actual backend. Keep project-specific materials, thresholds, videos and budgets with the receiving game.

When a finite drop expands before contact, check the initial neighbour spacing and rest density. Advect the incoming sites with the falling body during admission. For a visible whirlpool, localize the inlet, transport an asymmetric tongue toward the centre and fade outgoing water as it actually crosses the drain. A symmetric rotating ring can hide the motion even when angular momentum is correct.

Profile the contact interval separately from free flight. Dense neighbourhoods can dominate overlapping casts. Preserve the physical support radius and iteration order when filtering candidate neighbours. Re-render the final GPU program and compare its solved state, silhouette and cost against the preceding version.

## Compare two independent replays

Inspect the serialized initial-event name before choosing a reset sequence. Reinitializing a Graph can submit its initial event, so a subsequent explicit Play can produce a second burst. Measure the first birth and the last live particle across disable, stop and reuse. A delayed echo is another distinct clock. Take its offset from the actual primary release, keeping any projectile travel time and contact event separate.

1. Verify native import, dependencies, shader passes and Graph kernels on the receiving graphics backend. Capture the production entry or prefab at gameplay scale and speed. Record the source revision, package versions, seed, simulation tick, camera, phases and rendering backend.
2. At a matched time capture the full image, Graph contribution and shader contribution. Hide the respective renderers independently or neutralize an input actually consumed by an integrated output. Restore each value immediately. Record the changed pixels and locate them on the intended landmark. Alive counts alone cannot establish a layer's visibility.
3. Replay the same source from fresh instances in a second native process. Compare onset, peak, contact, ordering, silhouette and cleared tail across runs, including cancellation or retrigger where applicable. Report tolerance in frames and image space at the capture resolution. Check the timing study and [judge fidelity directly against the original](rendering-and-verification.md#compare-the-native-effect-with-the-original). Allow for stochastic differences only where the brief permits them.
4. When the two runs reproduce a wrong image, return to the numbered jobs. Record the failing phase, observed symptom, source mismatch, implemented correction and evidence from the rerun. Keep the case and its exact measurements with the game and promote reusable mechanisms here.
