# Repository and delivery

The public Unity Skill packages and project guidance are versioned here. Users may improve the shared guidance while solving a task. The verified repository owner lands changes directly on upstream `master`. After confirming delivery, release the task worktree and delete any merged task branch and tracking ref. Contributors open one PR from a fresh topic branch and verify its exact head for maintainer review. Record the problem, rationale, and verification in the owner's commit or the contributor's PR. Keep local Cache, credentials, and private game data with their own owners. [Contribution workflow](../../../unity-code-skill/references/contributing.md#submit-a-skill-change)

Stage the generated marketplace alongside packaged Skill edits with the [shared publisher](https://github.com/qinbatista/qin-codex-skills/blob/master/.github/actions/publish-plugin/publish.py) using `--project-root <checkout> --plugin qin-unity-skills --prepare`. Verify the candidate package before submission. The [publish action](../../../.github/workflows/publish-plugin.yml) keeps the native marketplace current on `master`. Release verification checks that the [grouped installer](../../../README.md#install-the-global-skill-pack) can read all six Skills from the merged `master` archive.

All six entries state project precedence and link to the [standalone CLI gate](../../../unity-code-skill/references/unity-cli.md#standalone-cli). Unity Code owns the portable launcher. Projects with a declared workflow use their runner and its tool startup policy. Linked projects get CLI update timing from the registered YoFaAssets source and share the per-installation daily record.
