# Unity Code

For ScriptableObject fields, ownership and save compatibility use the [ten data contract checks](../../../unity-code-skill/references/scriptableobject-data-contracts.md#design-and-review-a-data-owner). The [spell catalog](../../../unity-code-skill/assets/SOSpellCatalog.cs) owns the keyed value-record example. The [wallet](../../../unity-code-skill/assets/SOPlayerWallet.cs) owns local v1 migration, the current save and the full online projection. The [foundation replay](../../../.agents/skills/testing-skill/SKILL.md#run-the-foundation-fixture) loads the previous writer's bytes.

The [SODataController template](../../../unity-code-skill/references/so-data-controller.md) attaches storage to an existing runtime SO with its original base, fields and methods. The [compiler pass](../../../unity-code-skill/assets/CodeGen/SODataFieldWrites.cs) observes assignments. The [session](../../../unity-code-skill/assets/SOKeySession.cs) writes one changed key locally or queues it for online acknowledgement. Indirect edits have an owner checkpoint. The [native fixture](../../../.agents/skills/testing-skill/SKILL.md#run-the-foundation-fixture) verifies legacy readers, failures, and SDK integration. The [Singleton reference](../../../unity-code-skill/references/unity-game-code-structure-design.md#singleton-managers) owns scene registration and teardown.

The [local-first cloud save reference](../../../unity-code-skill/references/local-first-cloud-saves.md#implement-a-local-first-save) owns the ScriptableObject, local JSON commit, and provider adapter contract for offline-capable games. The receiving game owns its current schema, slot and gameplay checkpoints. Provider-specific code implements the neutral procedure at the installed SDK boundary.

Use the [Skill entry](../../../unity-code-skill/SKILL.md) for direct calls and state ownership. The [frame-callback reference](../../../unity-code-skill/references/unity-lifecycle-and-serialization.md#frame-callbacks) owns admission and settled requests. [Runtime resources and GC](../../../unity-code-skill/references/runtime-resources-and-gc.md) owns mode-specific destruction, leases, native data, bounded reuse and calibrated allocation evidence. [Service integration](../../../unity-code-skill/references/unity-service-integration.md) owns SDK and transaction boundaries. Linked games first use their current YoFaAssets and local system contracts.

The [completed Job batch contract](../../../unity-code-skill/references/unity-game-code-structure-design.md#completed-job-batches) keeps root movement in the movement Job and assigns completed-state publication to the Manager. Review the Job's position write, one read-only batch after completion, and each Controller's indexed animation or local-state read and subscription lifetime.

The [Job State Batches sample](../../../examples/job-state-batches/README.md#five-scenes) demonstrates the same contract in five independent systems. Each saved scene exercises movement while its presentation Controller is detached and applies the completed state when subscribed.

The [pack task menu](../../../unity-code-skill/references/global-skill-routing.md#choose-by-task) handles mixed or unclassified Unity tasks. Its [section reader](../../../unity-code-skill/scripts/read_topic.py) resolves links relative to the selected domain and preserves enclosing instructions.

The [C# checker](../../../unity-code-skill/scripts/csharp_rule_guard.py) reports lexical findings. It distinguishes wildcard arrows from discard assignments and same-name overloads or other receivers from likely self-recursion. Its [Git scope](../../../unity-code-skill/scripts/qin_rule_guard_common.py) and [hidden-process](../../../unity-code-skill/scripts/hidden_process.py) helpers mirror the shared [Code Skill scripts](https://github.com/qinbatista/qin-codex-skills/tree/master/code-skill/scripts) for standalone installation. Use the [test map](../../../.agents/skills/testing-skill/SKILL.md) for the checker and installed-package routes.
