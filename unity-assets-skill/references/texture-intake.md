# Texture intake and import

## Select the workflow and scope

Start with the receiving project's asset rules, presets, import hooks and declared targets. A project-specific PPU, world calibration, import policy or runner governs its scope. For a linked project, consult its registered YoFaAssets `explain texture-compression` and use the source-owned workflow for the linked steps. In a project with no such workflow, execute the standalone procedure here using native Unity importers and the CLI. Where a linked handoff is unavailable, report the affected step and continue local work allowed by the project.

Audit the exact images read, received, generated, edited or reused in the current Unity task, including reused imports with matching names. An explicit folder or whole-project request expands that scope. Complete native intake for new production art and apply verified settings before handing it to the consumer. During routine reuse, apply proven lossless savings within the task's write scope. For authorized intake and optimization, the Skill selects and applies any acceptable quality-changing settings using the actual display checks below. Honor read-only and no-run requests.

## Bind source and receiver

- Record the exact source and destination, revision, byte digest, decoded dimensions, format, visible alpha bounds, intended role and consumer. Preserve the accepted master and bind any delivery derivative to it by digest. Reopen the delivered bytes and check the intended size and transparency before native import. Check decoded alpha for cutouts, silhouettes and translucent edges. A painted checkerboard stays opaque.
- Trace Prefabs, scenes, materials, UI, animation, atlas membership, scripted pixel reads, collider geometry and dynamic Addressables or Resources where applicable. Record unknown, protected, unavailable and vendor uses explicitly. A source with no receiving asset path is pending native intake.
- Verify that base art and companion maps share source revision, alignment and the dimensions, channels, precision and color interpretation the material expects. Verify the affected material and lighting states after import. A changed map layout or crop requires renewed alignment.

## World Sprite scale

Use the project's stated PPU and unit calibration wherever supplied.

### Size new world art

For new world-space Sprite art with no project-specific standard, author and import at **1000 PPU** and use **1 Unity world unit for 1 meter**. At effective Transform scale 1, 1000 authored pixels span 1 unit and 1 meter. A 0.35 m visible width takes 350 visible pixels under this default. Measure transparent padding separately and budget each frame of a Sprite sheet. Derive UI size from layout and rendered device pixels. Use the pixel and channel contract of ordinary textures and data maps. For UI Sprites, preserve the consumer's reference PPU, slicing and layout scale.

### Verify imported world size

Set authored PPU before placing new Sprites. Read the importer value, each native `Sprite.pixelsPerUnit` and the resulting bounds on both world axes under the actual hierarchy scale. A platform cap can change native dimensions and effective PPU. Convert any simulation coordinates using the project's calibration before choosing authored pixels.

### Migrate an existing Sprite

For an existing Sprite, migrate PPU only within a sizing change's authorized scope. Inspect actual world, UI, rig, animation, tiled, collider and baked consumers first. With identical pixels, a simple renderer-only leaf can preserve size by multiplying local XY scale by `new PPU / old PPU`. Verify the other consumers at their own geometry and lifecycle boundaries. Compare both axes, rounding, slices, local IDs, UVs, pivots, borders, render meshes and physics outlines. Keep the prior geometry whenever preservation cannot be established.

### Trace sizing drift

Locate sizing drift in the source canvas, export, copied file, importer or consumer. Preserve the correct original and version any corrected derivative. Recompute pixel-coordinate geometry and companion-map alignment where changed. When the target size is known, correct the earliest wrong stage in the owned derivative or importer. For example, a one-meter object exported at twice its approved linear density can be re-exported from its master at 1000 visible pixels per meter. Preserve the authored canvas-to-pivot offset. Verify the placed bounds after reimport and remove any obsolete scale compensation on the render-only leaf. If the source is correct and only the loaded texture is excessive, keep the source and trial a smaller target cap. Changing PPU alone changes placement and leaves the texture payload intact.

### Build resizable world sprites

Inspect the ground period, tree base, trunk and crown beside their [native Unity renders and import measurements](https://github.com/qinbatista/qin-unity-skills/tree/master/examples/image-optimization). Run the [installed woodland replay](../../unity-performance-skill/references/performance-cases.md#replay-the-image-optimization-examples) to reproduce the world, UI, import and atlas cases. Resize the examples through the same SpriteRenderer properties used below.

Choose one seamless period at the intended world density. Keep unique silhouettes, landmarks and end pieces as separate art or fixed borders. A 250 × 125 pixel ground period at 1000 PPU covers 0.25 × 0.125 m at unit scale. An 8 m strip uses the same period 32 times. Budget its import for the largest on-screen size of **one period** at the closest supported camera.

Compute the cap from both axes. Suppose the maximum supported zoom renders that period's **visible** 250 × 100 source pixels at 175 × 70 screen pixels, with transparent margins only above and below the horizontal repeat. The full 250 × 125 source canvas, including transparent margins, then needs at least 175 × 87.5 imported pixels. Compute the required fraction as the larger of `175/250` and `70/100`, then multiply the longest full-canvas side by that fraction and round **up** to the next supported Max Size (256 here). Unity preserves the aspect ratio and can keep this 250-pixel source at its original size. For an 8 m strip with **32** periods, use the projected pixel width of one period. If the closest camera draws it at only half that screen size, the first candidate cap is 128. Check native dimensions after importer rounding and inspect a rendered seam at that zoom. If the effective cap is already smaller and looks undersampled, test a higher cap against the original master through the existing sizing procedure.

- **Ground.** Import a seamless Single Sprite with Full Rect mesh and zero border. Bind it to one `SpriteRenderer` with Draw Mode **Tiled** and Tile Mode **Continuous**. At unit scale set `SpriteRenderer.size` to (strip length, tile height) in local units. Drag the renderer's Rect handles or edit Size to extend the strip. Keep the Transform at its authored scale. Test a fractional last tile as well as a complete period. Use a Tilemap for independently edited cells or cell-specific gameplay.
- **Tree.** Author one base, one vertically seamless trunk period and one crown with compatible join widths. Keep the base and crown at native size. Use a Tiled/Continuous renderer for the body, set its width to one period and its height to the requested tree height minus both cap heights. Author joins and pivots so the base stays at the planting point and the crown follows the trunk's upper join. Set the minimum to the combined cap heights and hide the body at zero. A single Full Rect sprite with top and bottom borders also works when both caps and trunk share the same rectangular canvas. Validate the collider, sorting and shadow at the shortest and tallest sizes.
- **Reuse.** Share the same Sprite references and material across size variants. Inspect at normal and maximum zoom for frequency changes, exposed seams, clipped end details and alpha bleed. Keep ground collision with its geometry owner. Long tiled renderers generate geometry per repeat. Check visible geometry and culling at the maximum extent and chunk very long runs when needed. [Unity tiled Sprite rendering](https://docs.unity3d.com/6000.0/Documentation/ScriptReference/SpriteDrawMode.Tiled.html)

For a standalone import trial, copy the [WorldRepeatSprite Editor helper](../assets/Editor/WorldRepeatSprite.cs) into an Editor folder of an isolated receiver. Use a dedicated, unrigged, rendering-only Single Sprite with no CPU reader or authored shape dependency. Measure the maximum projected full-canvas width and height of one period, including its padding, and round fractional pixels up. In the example above, pass 175 × 88. Run the following expression through the [scoped CLI import procedure](#execute-and-verify-the-import) with that receiver and its active importer platform.

```csharp
Qin.UnityAssets.WorldRepeatSprite.ConfigureForDisplay("Assets/World/GroundPeriod.png", "Standalone", 175, 88)
```

The helper reads the original source dimensions, converts both screen bounds to a longest-side requirement and rounds up to a supported cap (minimum 32). When the projection exceeds the source, it retains available source detail. A requirement above the supported 16384 cap fails before applying changes. For an already reviewed explicit cap, call `ConfigureImport(path, platform, maxSize)`. Both entries set authored PPU to 1000, Full Rect mesh and Read/Write off. They lower the effective active-platform cap only when needed, preserve its format selection and other targets' overrides, and return false for matching settings. A pre-existing lower cap remains in force. Recheck that case against the requested display and record any shortfall. A conflicting import policy fails the trial. Discard a failed candidate. Read back the effective pixels per unit, the period bounds and rendered result before promoting a successful trial. For a legacy shared asset use the [existing Sprite migration](#migrate-an-existing-sprite) and the consuming project's workflow.

### Pack sprites that load together

Share a Sprite directly for copies with the same image, import contract and lifetime. Before consolidating duplicate files, verify GUID consumers and dynamic loads. Pack distinct Sprites into a Sprite Atlas by screen, scene or other shared loading lifetime. Choose page size, platform compression, padding and filter settings from the packed output. Inspect page count, empty space, page bytes and the load footprint when only one Sprite is visible. A large mixed-lifetime page can increase memory.

For tiled and sliced art, keep rectangular regions, give adjacent sprites enough padding for the chosen filtering and mips, and turn off rotation for consumers that require upright packed UVs. Native SpriteRenderer tiling confines each repeat to the Sprite. A material that repeats texture UVs samples the whole texture, so use a dedicated repeat texture for that shader or implement verified atlas-region sampling. Check the packed result alongside its neighbors, the batched draw calls and loaded textures in the receiving scene. [Unity Sprite Atlas workflow](https://docs.unity3d.com/Manual/SpriteAtlasWorkflow.html)

## Choose settings by use and target

Classify by the decoded image and its real use. Choose texture type, sRGB or linear sampling, alpha handling, filtering, wrap, mipmaps, readability, Max Size and platform overrides together. Use the strictest verified requirement across all consumers. Preserve readability and pixel dimensions for CPU reads, collision masks, lookup values, font/SDF data and coordinate-based crops until their owners prove a safe change.

### Settings by texture role

| Use | Import and quality checks |
| --- | --- |
| World Sprite, including painted or transparent art | Use Sprite import and the intended Single or Multiple layout. Preserve authored slices, pivots, mesh, outline and borders. Use color sampling for display art and preserve required alpha. Choose filtering and mips for actual camera range. Check silhouettes, fine brushwork and transparent edges. |
| Pixel art or tiles | Start with Point filtering and original pixel dimensions. Keep mips off for pixel-exact rendering unless the project's minification policy calls for them. Keep an exact encoding for pixel or palette-sensitive use. Check seams, atlas padding and the intended integer scale. |
| Screen-space UI, icons and nine-slices | Match the actual Sprite or Texture2D binding. Preserve text legibility, borders, alpha and atlas layout. Check light and dark backgrounds and the largest supported viewport. Enable mips only when the real UI consumer benefits. |
| Material color, backgrounds and VFX | Use sRGB for color and linear for data channels. Choose Clamp or Repeat from sampling, and mips from the real distance and minification range. Check gradients, seams, emission, soft edges and alpha in the actual material or effect. |
| Normal, packed mask, HDR and other data textures | Select the actual importer type and required linear or HDR precision. Preserve channel semantics, alignment, bit depth, readability and dimensions as required. Keep the established representation while the data contract is unknown. |

### Resolution and mip streaming

Derive a safe Max Size from the largest evidenced display footprint, frames, transparent padding, camera zoom and reuse. Preserve source resolution and the current cap until evidence supports a size change. A declared test profile supports only its tested resolution and zoom. Keep exact pixel coordinates, non-power-of-two dimensions and geometry where required. For mip streaming, identify all consumers and their demand and quality settings before enabling it. Check actual residency and the displayed result.

### Target formats and Crunch

Start with the project's validated format or Unity's Automatic format for the target. Test supported candidates where compression is appropriate, such as ASTC on supported mobile devices, ETC2 on compatible Android fleets, and BC formats on compatible desktop targets. Choose block size and alpha support from the actual asset. Verify the target GPU and any fallback, including WebGL browser support. Review atlas platform overrides and the effective packed texture for atlas consumers.

Treat Crunch as an optional download or build-size optimization for a supported DXT or ETC format on the target. Compare the same base GPU format with and without Crunch, using actual encoded bytes, decoded appearance and representative loading cost. Unity expands Crunch data into its base GPU format for upload. Estimate GPU storage from the actual GPU format, dimensions and mips. For ASTC, compare block sizes and quality. Use a higher-quality format when artifacts violate the intended result. [Unity platform texture settings](https://docs.unity3d.com/Manual/class-TextureImporter-type-specific.html)

## Execute and verify the import

1. After source review, check eligible PNG delivery copies for lossless savings with a local encoder. Prefer recompressing image data while preserving the other chunks, palette, transparency and color profile. With no local encoder, use Python's `zlib` on a validated static PNG. Recompress the concatenated IDAT stream and rebuild its chunk length and CRC while copying every other chunk verbatim. Validate the output and require identical inflated image data and metadata, a smaller file and an exact source-to-delivery digest binding. Keep byte-exact and unsupported inputs at their original encoding. Source file savings are independent of Unity's texture encoding.
2. Use the project's native import command or preset when it exists. For standalone work, use the [Unity CLI workflow](../../unity-code-skill/references/unity-cli.md#standalone-cli) and the Editor version pinned by the receiver. Prefer an available native asset command. With a connected instance of that project and Pipeline support, use `unity command script eval --caller plugin --skill unity-assets-skill --project-path "<receiver>" "<scoped C# operation>"`. A batch route can run an Editor-only method through `unity run "<receiver>" --non-interactive --no-pager --log-file "<task-run>/texture-import.log" -- -executeMethod <Class.Method>`. Forward standalone commands through the documented launcher. Keep transient adapters, candidate imports and logs in the task-owned Cache. Use an isolated project snapshot with matching importer dependencies for batch candidates when the receiver has no maintained method.
3. Place only the approved file in the declared asset owner, verify its delivery digest and preserve its existing `.meta` on replacement. In the native operation, use `AssetDatabase.ImportAsset` for the exact `Assets/...` path and check its actual importer with `AssetImporter.GetAtPath`. For `TextureImporter`, read current settings and `GetPlatformTextureSettings` first. Apply the reviewed fields such as `spritePixelsPerUnit`, and write reviewed target overrides through `SetPlatformTextureSettings`. Call `SaveAndReimport` and reopen the asset. Use the actual importer for layered PSD/PSB or other scripted sources and verify its rig or importer output. For an isolated trial, promote only the validated native-generated asset or importer metadata after matching the live source and metadata preimages, then reimport through the receiver's CLI.
4. Compare each candidate against the full pre-change native reference at the same largest supported display scale. Include downsampling, alpha and every affected channel in the comparison. Lossless native changes require identical decoded channels at every affected mip and matching geometry and data behavior. For visual optimization, inspect the decoded candidate at display size in its consumer, including its most sensitive detail. Select the smallest measured candidate meeting the contract. Restore the prior scoped settings and verify the restored import if a change fails.
5. Read back the actual imported texture and Sprite subassets, including effective dimensions, format, PPU, mips, target overrides, GUID and local fileIDs. Compare the applicable atlas, slicing, collider, material or UI consumer after reimport. Record delivery file bytes, platform storage and observed runtime residency as separate measurements. If a built Addressables bundle depends on the texture, use the project's content build workflow when authorized and read the consuming bundle before claiming it has the new import.

For repeat work, reuse a prior result only when the source digest, importer metadata, Editor, target, policy and measured usage match. Use the project's MD5 detector where it already records one. Preserve current accepted detailed results across routine audits. Reevaluate changed inputs and reconcile concurrent edits before applying an isolated result. Report scanned, changed, reused, protected and pending paths, actual savings and the tested display scope.
